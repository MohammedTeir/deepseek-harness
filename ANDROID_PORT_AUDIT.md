# Android repository audit

## Summary

Phase 0 and Phase 1 reference for the checked-out fork. The authoritative scope is `DEEPSEEK_HARNESS_ANDROID_MASTER_PROMPT.md`, narrowed by the author's instruction to stop before Phase 2. No Android application, runtime integration, workflow, frontend, or agent implementation is changed by this branch. [Exact baseline](audit/android/baseline.json) records the fork revision, original upstream ancestor, separately observed current upstream HEAD, lock digest and host tools. Upstream has advanced; no upstream source update was applied.

## Dependency coverage

The [resolved graph](audit/android/dependency-graph.json) includes all 394 lockfile importers, 1,762 peer-context snapshots representing 1,755 package metadata identities, and 8,696 resolved dependency edges with zero missing targets. Dependencies, development dependencies, optional dependencies, link targets, npm aliases, peer declarations, peer contexts and transitive-peer annotations are retained. Cycles are traversed with a visited set. No platform filter removes optional binaries. The graph covers the committed pnpm lockfile, not arbitrary future plugins or programs downloaded at runtime.

[Installed payload inspection](audit/android/package-inspection.json) covers 1,426 locked package identities, inspecting manifests, lifecycle scripts, native source extensions/build descriptors, binary signatures and ELF headers/interpreters/DT_NEEDED. [Registry manifests](audit/android/registry-manifests.json) cover the remaining 329 identities; all returned distribution integrity values match the lockfile. Their actual archive contents remain uninspected. No inspected root package manifest declares `bundledDependencies`/`bundleDependencies`; bundled payloads still exist and were found by file inspection. Registry metadata is not executable compatibility evidence, and an absent install hook is not proof of pure JavaScript. Bundled files in installed packages are scanned; dynamically fetched browser/engine/model assets and nested dependency declarations outside the lockfile remain explicit supply-chain risks.

[Native dependency paths](audit/android/native-dependency-paths.json) show concrete transitive paths from CLI, minimal SDK, frontend build and desktop build roots. Production-plus-optional closure sizes are CLI 696, desktop host 699, base bundle 460 and sdk-minimal 178. These counts include the root and workspace nodes, not just npm packages. They are install closures, not proof that every dependency executes at boot. `apps/web` has only two production closure nodes because its compiler inputs are devDependencies; use its build paths and full graph, not that production count, to assess the frontend.

The audit is based on dependency edges and package/source contents, not package names alone. [Source API index](audit/android/source-api-index.json) records 36 imported Node builtin module specifiers, 374 platform/process sites and 17 tracked native-source/build-matrix paths. Tests and browser-only stubs must not be mistaken for required runtime imports; paths let reviewers distinguish them. Install hooks and compiler entrypoints were inspected, not executed by the scanner.

## Actual application architecture

`apps/cli/src/profile-boot.ts` runs the supported profile launcher. `packages/boot/app-boot` resolves ordered profile bundles and overlays into a Cordis tree. `packages/bundle/base/cordis.patch.yml` supplies the common agent, model, tool, persistence and policy services; `packages/bundle/web-app` adds the original browser product. `packages/bundle/sdk-minimal/cordis.patch.yml` is a smaller authentic profile, but it still selects local subprocesses, terminal-bash and JSONL persistence. It is not an Android-ready composition or a replacement for the full model framework.

`apps/desktop-host/src/index.ts` calls `runProfile`, binds loopback on an assigned port, and reports boot/shutdown over Node IPC. Electron is a carrier, not the engine. `apps/desktop/src/preload-app.ts` exposes origin-scoped boot, file save/clipboard/drag, browser leases, keyboard/window, update and device integration. `apps/web/src/main.ts` treats `dshDesktopBoot` as optional: Android can retain the browser entry without implementing all Electron surfaces. Desktop-only features need explicit capability diagnostics.

`packages/core/agent-loop` assembles model requests from session history and commits tool calls/results. `packages/core/tools/src/index.ts` and its execution pipeline own pre-execute policy, approval and final guards before dispatch. `packages/interaction` carries human interaction; `packages/guard` contributes policy; `packages/llm` owns model-provider abstractions. `packages/core/session` records durable events; `packages/session/session-persistence-jsonl/src/lease.ts` requires native locking; `packages/storage/storage-sqlite/src/schema.ts` requires `node:sqlite`. UI events and streaming are separate from durable session records.

`packages/subprocess/subprocess-local` uses real `node:child_process` and lazily loads node-pty. Platform management includes Linux process/containment assumptions. `packages/shell`, `packages/terminal` and `packages/fs` expose existing seams to adapt. `packages/mcp/mcp-client/src/transport.ts` uses Streamable HTTP separately from SDK-owned stdio spawning; changing only the Harness subprocess provider does not intercept that stdio path. `packages/boot/plugin-manager`, extensions and package installation must be included in the trusted-code policy.

## Frontend and transport

`apps/web/src/main.ts` imports the original client Web shell and branding font; Vite builds `apps/web/dist`. `apps/web/vite.config.ts` uses `base: './'`, explicit index/preview entries, hashed chunks, separately emitted fonts and preview-worker assets. Client plugin bundles are loaded dynamically through `packages/client/modules`; a shell-only copy omits runtime boot injections and module registration. The private preview worker is not evidence of Node or Android backend compatibility.

`packages/host/frontend-static/src/index.ts` authenticates the index and applies server injections. It serves index only at the configured index/root; missing paths are 404, not a blanket SPA fallback. Source searches found no conventional browser-history router in the inspected client sources: workspace/settings/chat surfaces are plugin/slot driven (`packages/client/ui-workspace`, `ui-settings-shell`, `ui-dockkit`). Android deep links must be specified and tested rather than assuming arbitrary routes already work. Relative asset paths must be resolved from the same document base, and missing JS/API resources must never receive index HTML.

`packages/client/connection` authenticates Host/Origin, exchanges a launch token for authority-bound cookies, and admits browser/API peers. `packages/api/gateway/src/stream-protocol.ts` defines `/api/remote.mux`, the multiplexed WebSocket channel for Typert Remote streams. `packages/api/gateway/src/client/stream-client.ts` resolves the stream URL against `__DSH_TRANSPORT__.streamBaseUrl` or `document.baseURI` and selects ws/wss from the scheme. No explicit CSP declaration was found in the inspected Web entry, host source or desktop web-document source; do not claim a CSP is already enforced. A virtual HTTPS AssetLoader origin does not automatically satisfy the existing loopback cookie/origin model. Index injections, dynamic assets, RPC, streaming, token removal, cookie security and restart/reconnection all require integration tests.

## Scope limits

The MIT license and `SAFETY.md` remain authoritative: developer preview, not security-audited. Native and downloaded dependencies have additional license/distribution obligations: inspected node-pty and Koffi manifests report MIT, sharp reports Apache-2.0, and workspace node-addon-system is BSD-3-Clause. Those labels do not discharge licenses of bundled libraries, fonts, engine assets or downloaded programs; retain original notices and inspect each distributed payload before APK distribution. The complete locked graph is recorded; payload verification for 329 noninstalled packages, dynamically fetched artifacts, actual Android ABI behavior and every plugin's device behavior remain unverified. See [compatibility](ANDROID_COMPATIBILITY_MATRIX.md), [security](ANDROID_SECURITY_MODEL.md), and [review gate](ANDROID_IMPLEMENTATION_PLAN.md).
