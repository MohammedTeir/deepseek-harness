# Phase 1 audit evidence

This reference covers the locked repository graph and the inspected host installation. It contains no Android implementation or simulated runtime evidence.

- `baseline.json`: exact fork/upstream revisions and environment; upstream observation is not a source update.
- `dependency-graph.json`: all importers, resolved snapshots, typed edges, peer metadata and production-plus-optional closures. Zero unresolved edges is required.
- `native-library-graph.json`: binary payload nodes and actual ELF DT_NEEDED edges; OS/loader resolution remains unverified for Android.
- `workspace-policy.json`: reviewed install-hook allow/deny policy, overrides and patched-dependency digests.
- `graph-summary.json`: recomputable counts.
- `package-inspection.json`: installed manifests, lifecycle hooks, native source/build descriptors, binary signatures and ELF linkage; absent payloads are explicitly unverified.
- `registry-manifests.json`: metadata for all 329 noninstalled identities; distribution integrity matches the lockfile, but archives were not downloaded/executed. Registry distribution records retain tarball URLs, hashes, size/count fields and signatures when supplied; attestations are not stored or verified.
- `native-dependency-paths.json`: concrete dependency paths; CLI/minimal roots exclude dev edges, frontend/desktop build roots include them.
- `source-api-index.json`: builtin imports, platform-sensitive source locations and native source/matrix files; presence is not proof a minimum profile loads each site.
- `platform-references.json`: retrieved official guidance and explicit retrieval failures.

Run `python3 audit/android/collect.py` with Python 3, PyYAML and GNU readelf to regenerate graph and installed-payload evidence. No lifecycle hooks run. Resolve scanner errors instead of ignoring them. Registry and platform records are dated reference snapshots, not live dependencies. The source and path indexes were generated by the companion `index_sources.py`; run it after collection. The registry fetcher is `registry_manifests.py`; it only reads metadata and reports errors.

Graph completeness means the committed lockfile is fully represented, including optional/platform entries. It does not imply complete Android compatibility, inspection of absent archives, or coverage of future plugins/downloaded browser engines/model files. Bundled binary files in installed packages are inspected; dependencies hidden in downloaded/bundled programs remain review risks. No Phase 2 runtime strategy has passed qualification.

Payload traversal inspects real files and does not follow filesystem symlinks, preventing recursive traversal of pnpm dependency links. Package links are represented by lockfile edges; linked payload targets outside those scanned trees are not verified by this inventory. Native-library dependency names are recorded without claiming Android loader resolution or recursively certifying OS libraries.
